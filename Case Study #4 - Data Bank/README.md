## Case Study #4 - Data Bank

### Description
>This is the FOURD of eight challenges I will be solving over the next eight weeks.

### Problem Statement
> Data Bank is a next-generation digital bank inspired by neo-banks, combining banking, cryptocurrency, and secure data storage. Unlike traditional banks, it offers cloud data storage to customers, with storage limits tied to their account balances.

> As the business scales, the Data Bank team aims to grow its customer base and needs support to analyze usage patterns, forecast storage needs, and calculate growth metrics. 

> This case study focuses on leveraging data to support strategic planning and future expansion.

>This case study also aims to mimic traditional banking style transactions data but with a twist.

### What to spect

> Data cleaning
> Basic SELECT statements
> Aggregate functions (COUNT, SUM, AVG, MIN, MAX)
> GROUP BY and ORDER BY clauses
> JOINs (INNER JOIN, LEFT JOIN)
> Common Table Expressions (CTEs) using WITH
> Window functions (e.g., SUM() OVER, ROW_NUMBER() OVER, PERCENTILE_CONT() OVER)
> Subqueries (nested SELECT statements)
> Conditional aggregation (using CASE WHEN)
> Date and time functions (FORMAT, DATEDIFF, etc.)
> Aliasing columns and tables
> Filtering with WHERE and HAVING
> Percentile calculations
> Calculating running totals and balances
> Calculating percentages
> Interest calculations using arithmetic expressions

### Setup and Tools
